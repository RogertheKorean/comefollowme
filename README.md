# 함께 · Together Insights — v3

**공과를 읽다가, 옆에서 참조자료를 읽고, 그 자리에서 생각을 나누는 독립 웹앱 시연본.**

한국어가 기본이며 영어로 전환할 수 있습니다. 데이터베이스, 로그인, API 키 없이 실행합니다. 기존 v2 위에 공통 참조자료 패널과 콘텐츠 등록·연결 검사 기능을 구현했습니다.

## 오늘 바로 배포하기

1. ZIP을 압축 해제합니다. **ZIP 파일 자체가 아니라 압축 해제한 파일과 폴더**를 GitHub 저장소에 올립니다.
2. `package.json`, `vercel.json`, `src/`, `content/`, `scripts/`가 저장소의 같은 최상위 폴더에 있어야 합니다.
3. Vercel에서 새 프로젝트를 만들고 해당 저장소를 Import합니다.
4. 설정을 확인하고 Deploy합니다.

| 설정 | 값 |
|---|---|
| Framework Preset | **Other** |
| Root Directory | **`.`** — `package.json`이 있는 폴더 |
| Build Command | **`npm run build`** |
| Output Directory | **`public`** |
| Install Command | `vercel.json`에서 빈 문자열로 지정; 외부 패키지 설치 불필요 |
| Environment Variables | **없음** |

`vercel.json`에 빌드 및 출력 설정이 포함되어 있습니다. 실제 사용자 저장소나 Vercel 계정에 대한 배포는 수행하지 않았습니다.

GitHub에 상위 폴더를 통째로 올린 경우에는 Vercel의 Root Directory를 그 폴더로 지정하세요. 404 또는 빌드 실패 시 가장 먼저 `package.json`과 `scripts/build.mjs`가 그 위치에 있는지 확인합니다.

## 브라우저에서 즉시 시연

`index.html`을 Chrome/Edge에서 직접 열어도 작동합니다. 파일 미리보기 서비스 대신 실제 브라우저에서 파일을 여세요. 브라우저 정책에 따라 로컬 저장·이미지 캡처가 제한될 수 있으므로 **본 시연은 Vercel HTTPS 주소를 권장**합니다.

Node.js 20 이상으로 로컬 서버를 실행할 수도 있습니다.

```sh
npm run build
npm start
# http://127.0.0.1:4173
```

외부 npm 패키지나 설치 과정이 없습니다. `npm start`는 개발용 로컬 서버이며 Vercel 서버 프로세스로 실행하는 명령이 아닙니다.

## 달라진 기능

- 성구·연차대회·교재·기타 자료의 주소를 공통으로 분류하여 오른쪽 패널에서 처리합니다.
- 공과 본문과 패널의 링크는 외부 사이트로 자동 이동하지 않습니다. 출처는 텍스트와 **주소 복사**로 제공합니다.
- 패널 내부 문장 선택, 절/문단 번호 선택, 형광펜, 읽기 영역 이미지와 생각 작성이 작동합니다.
- nested link → 이전 자료로 돌아갈 때 읽던 위치와 선택을 복원합니다.
- 기록에 원문 언어, 문단 ID, 글자 위치, 인용문, 판본/버전을 저장합니다. 새 본문을 등록해도 이전 기록이 다른 문장으로 옮겨 붙지 않습니다.
- **참조자료 관리**에서 링크 수, 자료 종류, 언어별 전문/발췌/요약/미등록 상태와 확인할 수 없는 문단을 봅니다.
- Markdown/텍스트/HTML 파일에서 참조 본문을 등록하고, 같은 주소의 링크를 그 본문으로 연결합니다. HTML의 실행 코드와 원격 미디어는 제거합니다.
- 콘텐츠 팩을 내보내 GitHub에 반영하면 다음 빌드에 포함됩니다. 개인정보 기록은 콘텐츠 팩에 들어가지 않습니다.
- 인사이트, 댓글, 공감, 개인 기록, 별도 발표 동의, 교사 나눔 보드와 큰 화면 발표는 로컬 데모로 작동합니다.

## 반드시 구분할 사항

**자동 링크 연결은 구현되어 있지만, 인터넷의 모든 연결 본문을 자동 수집하는 앱은 아닙니다.** 등록되지 않은 자료는 외부로 내보내지 않고 패널 안에 미등록으로 표시합니다.

**기본 연차대회 4편은 공식 전문이 아니라 출처를 참고해 작성한 짧은 시연용 학습 요약입니다.** 한국어·영어 모두 화면에 표시합니다. 정식 전문을 읽게 하려면 사용할 수 있는 본문을 아래 방식으로 등록하세요. 요약의 `summary-*` ID는 공식 말씀 문단 ID가 아닙니다.

- 한국어 공과: 사용자가 올린 원문을 v2에서 보존한 자료.
- 영어 공과: 기존 시연용 번역이며 공식 영문판이 아님.
- 성경 패널: v2의 개역한글/KJV, 11개 장의 관련 106개 절. 잠언 3장 외에는 발췌이며 모든 연결 성구가 들어 있는 것은 아님.
- 교재: 업로드한 공과에 인용된 학습자 나눔 관련 문단(p19)만 발췌.
- 그림·PDF·잡지 목록: 종류와 주소는 인식하지만 외부 파일을 자동 내려받아 표시하지 않음.

## 전문을 넣고 모든 접속자에게 보여 주기

1. 앱에서 **참조자료 관리 → 본문 넣기** 또는 **참조 본문 등록**을 누릅니다.
2. 원본 주소, 제목, 언어, 실제 수록 범위를 입력하고 본문을 붙여 넣습니다. 언어별로 별도 등록합니다.
3. **미리 보기 · 링크 검사**를 확인한 뒤 내용/이용 범위 확인을 체크하고 **이 브라우저에 연결**을 누릅니다.
4. **콘텐츠 팩 내보내기**로 `deployment-content.json`을 받습니다.
5. 저장소의 **`content/deployment-content.json`**을 그 파일로 교체하고 commit/push합니다.
6. 새 Vercel 빌드가 완료되면 모든 접속자에게 등록 본문이 기본 자료로 제공됩니다.

관리 화면에서 등록만 하고 끝내면 **그 브라우저에만** 들어 있습니다. 서버 저장 기능이 아니므로 다른 사람에게 자동 반영되지 않습니다. 콘텐츠 팩은 읽기 자료만 담습니다. 개인 기록 내보내기인 `Together_My_Journal.json`을 저장소에 올리면 안 됩니다.

위치까지 정확히 연결하려면 원문의 실제 ID를 유지하세요.

```md
{#p19}
이곳에 실제 p19 문단 본문을 붙여 넣습니다.

{#p_qUmpH}
숫자가 아닌 문단 ID도 유지할 수 있습니다.
```

HTML 파일의 `<p id="p19">...</p>`도 읽습니다. ID가 없는 일반 텍스트에는 로컬 ID를 부여하며, 이를 공식 위치와 일치한다고 속이지 않습니다.

## 데이터와 공개 범위

Vercel은 같은 데모 화면을 제공합니다. **여러 사람의 인사이트가 실제로 합쳐지는 서비스는 아닙니다.** 각 브라우저에 별도 저장됩니다. `나만 보기`와 교사 역할은 시연용 UI이지 서버 접근 제어가 아닙니다.

로컬 저장소는 암호화되지 않으며 브라우저 데이터를 지우면 기록이 사라집니다. 캡처를 여러 장 붙이면 용량이 빨리 늘 수 있습니다. 저장에 실패하면 화면에서 알리며, 기록 내보내기를 사용할 수 있습니다. 중요한 실제 개인정보는 넣지 마세요.

배포된 콘텐츠는 URL을 아는 사람이 읽을 수 있습니다. `noindex`는 검색 제외 요청이지 로그인·보호 기능이 아닙니다. GitHub 저장소를 비공개로 해도 별도로 배포한 사이트까지 비공개가 되는 것은 아닙니다. 자료 이용 범위와 시연 대상에 맞게 배포하세요.

## 파일 구조

```text
package.json / vercel.json
index.html                 바로 열 수 있는 최종 빌드
public/index.html          Vercel이 제공하는 동일 빌드
src/                       화면, 스타일, 참조 엔진, 등록·검사 UI
content/                   공과·성구·요약·배포용 추가 콘텐츠 팩
scripts/build.mjs          외부 의존성 없는 정적 빌드
scripts/serve.mjs          로컬 시연 서버
tests/                     단위 테스트 및 브라우저 시나리오
SOURCES.md / TESTING.md     출처와 검증 범위
START_HERE.ko.md            짧은 시연 순서
```

이 프로그램은 예수 그리스도 후기 성도 교회의 공식 앱이 아니며 복음자료실과 동기화하지 않습니다.
