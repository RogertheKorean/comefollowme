# 함께 · Together Insights

주별 공과와 연결된 말씀을 읽고, 인사이트와 댓글을 함께 나누는 독립 학습 웹앱입니다. 한국어·영어를 지원합니다.

- 서비스: https://comefollowme.vercel.app
- 저장소: https://github.com/RogertheKorean/comefollowme
- Supabase: `cbvshayydunhnkpsuahn`

## 주요 기능

- 주별 공과 카드 대시보드. 현재 기본 본문은 2026년 9월 7~13일 공과 한 주이며, 등록된 새 공과는 카드로 추가됩니다.
- 로그인·회원가입 없이 글·댓글·공감 남기기. 이름은 선택 사항입니다.
- 승인된 운영자만 이메일로 로그인해 콘텐츠 준비와 발표 도구를 이용합니다. 비밀번호 재설정을 지원합니다.
- **함께 생각하기**: 교사가 공과를 선택하면 공식 원문 주소가 자동으로 채워지며, 선택 사항인 포스터(PNG·JPG·WebP, 5 MB 이하)를 첨부할 수 있습니다. 방문자는 공유 링크에서 포스터와 읽기 자료를 보고 로그인 없이 바로 답글을 남깁니다. 질문은 `/questions`, 공유 주소는 `/p/<slug>`입니다. 기본 질문은 자동으로 만들지 않습니다.
- 질문의 각 답변에도 하트와 댓글을 남길 수 있습니다. 인사이트의 공감 버튼·댓글 표시·저장 코드를 재사용하며, 본인의 댓글만 삭제할 수 있습니다. 댓글 이름 자동 입력과 0.8초 기기 내 임시 저장을 지원합니다.
- **와드 일정**: 공개 일정은 달력·목록·조직 필터에서 한국 시간(UTC+9)으로 확인합니다. 공유 주소는 `/calendar`과 `/e/<slug>`입니다. 담당 권한을 받은 운영자만 일정·포스터를 임시 저장, 미리 보기, 게시, 수정, 취소 또는 삭제할 수 있습니다.
- 인사이트·댓글·공감의 Supabase 저장. 다른 기기에서도 이메일 계정의 기록을 불러옵니다.
- 일반 댓글과 질문 답글의 자동 임시 저장. 입력이 0.8초 멈추면 변경된 내용만 이 기기에 저장하고, 화면을 떠날 때 남은 변경을 저장합니다. 새로고침 뒤 같은 글에서 이어 쓸 수 있으며, 등록에 성공하면 초안을 지웁니다. 등록 전에는 공개되지 않습니다.
- 참조자료 패널 상단의 **공식 원문 열기**. 선택한 한국어·영어 원문을 새 탭에서 엽니다.
- 작은 화면, 터치 버튼, 입력창, 화면 키보드와 안전 영역을 고려한 모바일 레이아웃.

## 실행과 Vercel 설정

Node.js 20 이상에서 실행합니다. SDK는 라이선스와 함께 번들되어 있어 빌드에 npm 패키지 설치가 필요하지 않습니다.

```sh
npm run build
npm test
npm start
# http://127.0.0.1:4173
```

| 설정 | 값 |
|---|---|
| Framework Preset | Other |
| Root Directory | `.` |
| Build Command | `npm run build` |
| Output Directory | `public` |
| Install Command | 빈 문자열 |
| `SUPABASE_URL` | 프로젝트 HTTPS URL |
| `SUPABASE_PUBLISHABLE_KEY` | 공개 publishable 키 또는 legacy anon 키 |

두 환경변수를 Vercel에 등록합니다. 로컬에서는 `.env.local`에 넣을 수 있습니다. 빌드는 secret/service_role 키를 거부합니다. 두 변수가 모두 없으면 브라우저 로컬 모드이며 온라인 저장은 작동하지 않습니다.

## 계정과 데이터

읽기, 질문 보기, 일정 보기, 인사이트·댓글·공감과 질문 답글은 로그인 화면 없이 바로 이용합니다. 처음 쓰기 작업을 저장할 때만 브라우저별 Supabase 익명 식별자를 만들고, 이후 같은 브라우저에서 재사용합니다. 이름을 비우면 익명으로 표시합니다. 보기만 하거나 이름 설정만 저장하면 식별자를 만들지 않습니다.

공유 글·댓글·질문·질문 답글과 게시된 일정은 사이트 방문자에게 공개됩니다. `나만 보기` 기록은 Supabase RLS로 작성자만 읽도록 제한합니다. 다른 사용자의 글을 수정하거나 삭제할 수 없습니다. 운영 권한은 서버의 `together_staff`에서 부여하며, 가입하거나 화면 값을 바꾸는 것만으로 얻을 수 없습니다. 질문 게시와 일정 관리는 서버 역할 및 조직 범위로 제한되며, 가입만으로 권한이 생기지 않습니다. [권한 설정](docs/STAFF_ACCESS.md)을 참고하세요.

익명 글도 서버에 저장되지만, 브라우저 데이터 삭제 또는 운영자 계정으로 전환한 뒤에는 기존 익명 기록을 다시 관리할 수 없습니다. 이메일 계정으로 자동 이전되지 않습니다. 운영자 로그인은 사이드 메뉴 아래에서 열며, 이메일 확인 및 비밀번호 재설정 기능을 유지합니다.

등록한 글·댓글·공감은 서버에, 작성 중인 댓글·임시 글·형광펜·읽기 설정·로컬 등록 자료는 해당 기기에 보관합니다. **일정의 ‘임시 저장’은 서버에 비공개로 보관하는 기능**이며, 댓글 자동 저장과 다릅니다. 댓글 초안은 기기를 바꾸면 이어지지 않으며 브라우저 데이터를 지우면 삭제됩니다. 기존 로컬 기록은 사용자가 명시적으로 다시 저장할 때 계정에 업로드됩니다. 온라인 기록은 현재 계정으로 다시 조회하며 다른 계정의 비공개 기록을 표시하지 않습니다. 인사이트와 댓글 변경은 약 15초 간격, 질문과 일정은 약 30초 간격 또는 창으로 돌아올 때 확인합니다. 질문·일정에서 입력 중일 때는 배경 새로고침을 미룹니다.

## Supabase와 메일

`supabase/migrations/`에 테이블과 RLS 정책이 있습니다. `supabase/config.toml`은 이메일 확인, 비회원 인증, 비밀번호 길이, 서비스 주소와 재설정 리디렉션을 설정합니다.

현재 운영 프로젝트의 001~009 SQL은 검토 후 개별 쿼리로 적용했습니다. CLI 마이그레이션 이력이 자동으로 기록된 방식이 아니므로, 다음 변경에서 `db push`를 실행하기 전 실제 테이블과 마이그레이션 이력을 대조해야 합니다. 기존 테이블을 만드는 SQL을 그대로 재실행하지 마세요.

가입·재설정 메일은 `rogernhpark@gmail.com`의 Gmail SMTP로 발송하도록 구성되어 있습니다. 앱 비밀번호는 `SMTP_PASSWORD` 환경변수로만 전달합니다. 로컬 입력 파일 `.env.smtp.local`은 Git에서 제외되며, Vercel이나 브라우저 빌드에 포함하지 않습니다. Gmail 앱 비밀번호를 변경하면 Supabase의 SMTP 비밀번호도 갱신해야 합니다.

Supabase 설정을 CLI로 다시 적용할 때에는 `SMTP_PASSWORD`를 해당 프로세스의 환경변수로 준비한 후 실행합니다. 비밀번호를 소스 파일이나 명령행 인수에 넣지 마세요.

## 콘텐츠 범위

**기본 연차대회 4편은 공식 전문이 아니라 출처를 참고해 작성한 짧은 시연용 학습 요약입니다.** 한국어·영어 모두 화면에 표시합니다. 정식 전문을 읽게 하려면 사용할 수 있는 본문을 아래 방식으로 등록하세요. 요약의 `summary-*` ID는 공식 말씀 문단 ID가 아닙니다.

- 한국어 공과: 사용자가 올린 원문을 v2에서 보존한 자료.
- 영어 공과: 기존 시연용 번역이며 공식 영문판이 아님.
- 성경 패널: v2의 개역한글/KJV, 11개 장의 관련 106개 절. 잠언 3장 외에는 발췌이며 모든 연결 성구가 들어 있는 것은 아님.
- 교재: 업로드한 공과에 인용된 학습자 나눔 관련 문단(p19)만 발췌.
- 그림·PDF·잡지 목록: 종류와 주소는 인식하지만 외부 파일을 자동 내려받아 표시하지 않음.

## 공과를 분석하고 바로 게시하기

관리자 또는 콘텐츠 담당자로 로그인한 뒤 **공과 준비**에서 진행합니다.

1. **원문 넣고 분석하기**에 웹 원문에서 복사한 본문 또는 Markdown을 붙이거나 `.md`/`.txt` 파일을 선택합니다. 웹 복사에 포함된 제목·문단·링크는 Markdown으로 보존합니다. 영어는 선택입니다.
2. **본문 분석 · 기본 정보 채우기**를 누릅니다. 제목·기간·공과 원문 URL을 찾고, 없는 정보는 비웁니다. 날짜에 연도가 없으면 임의로 붙이지 않습니다. 언어별 링크 수를 표시하며, 주소가 없는 일반 텍스트는 원래 링크를 자동 복원하지 못하므로 웹 원문에서 다시 복사해야 합니다.
3. 자동 입력된 **공과 기본 정보**를 수정하고 **게시 전 미리보기**에서 본문과 언어별 문단 연결을 확인합니다.
4. 확인란을 선택하고 **공과 게시**를 누르면 Supabase에 저장되어 모든 방문자의 주별 대시보드에 표시됩니다. 콘텐츠 팩이나 재배포는 필요하지 않습니다.
5. 기존 공과는 상단에서 선택해 **불러오기 → 수정 → 미리보기 → 수정 내용 게시**합니다. 최신 버전만 카드로 표시하고 이전 버전은 기존 인사이트의 참조를 위해 보존합니다.

작성 중인 초안은 계정별로 현재 기기에 800 ms 입력 대기 후 저장됩니다. 게시 전까지 공개되지 않습니다. 본문 또는 기본 정보를 바꾸면 미리보기를 다시 확인해야 합니다. 같은 공과를 다른 담당자가 먼저 수정하면 덮어쓰지 않고 알립니다. 전체 게시 요청은 2.5 MB 이하입니다. URL만 입력한 자동 수집·자동 번역은 제공하지 않습니다.

## 참조자료 전문을 넣고 모든 접속자에게 보여 주기

1. 콘텐츠 권한이 있는 운영자로 로그인한 뒤 **참조자료 관리 → 본문 넣기** 또는 **참조 본문 등록**을 누릅니다.
2. 원본 주소, 제목, 언어, 실제 수록 범위를 입력하고 본문을 붙여 넣습니다. 언어별로 별도 등록합니다.
3. **미리 보기 · 링크 검사**를 확인한 뒤 내용/이용 범위 확인을 체크하고 **이 브라우저에 연결**을 누릅니다.
4. **콘텐츠 팩 내보내기**로 `deployment-content.json`을 받습니다.
5. 저장소의 **`content/deployment-content.json`**을 그 파일로 교체하고 commit/push합니다.
6. 새 Vercel 빌드가 완료되면 모든 접속자에게 등록 본문이 기본 자료로 제공됩니다.

위 **참조 본문 등록**은 **그 브라우저에만** 들어 있습니다. 공과 준비 화면의 **공과 게시**와 구분됩니다. 서버 저장 기능이 아니므로 다른 사람에게 자동 반영되지 않습니다. 콘텐츠 팩은 읽기 자료만 담습니다. 개인 기록 내보내기인 `Together_My_Journal.json`을 저장소에 올리면 안 됩니다.

위치까지 정확히 연결하려면 원문의 실제 ID를 유지하세요.

```md
{#p19}
이곳에 실제 p19 문단 본문을 붙여 넣습니다.

{#p_qUmpH}
숫자가 아닌 문단 ID도 유지할 수 있습니다.
```

HTML 파일의 `<p id="p19">...</p>`도 읽습니다. ID가 없는 일반 텍스트에는 로컬 ID를 부여하며, 이를 공식 위치와 일치한다고 속이지 않습니다.

## 프로젝트 구성

- `src/`: 읽기 화면, 참조자료, 계정·공유 저장, 대시보드, 모바일 UI.
- `content/`: 기본 공과와 성구, 명시적으로 표시된 학습 요약, 배포용 콘텐츠 팩.
- `supabase/`: 서버 스키마와 인증 설정. 비밀 값은 포함하지 않습니다.
- `public/index.html`: Vercel 배포 결과. `src/` 수정 후 빌드로 생성합니다.
- `tests/`, `TESTING.md`: 테스트와 실제 검증 범위.
- `AGENTS.md`, `.codex/config.toml`: 독립 작업을 분담하고 리드가 통합하는 에이전트 구성.
- `SOURCES.md`, `licenses/`: 본문 출처와 사용 라이브러리 라이선스.

이 프로그램은 예수 그리스도 후기 성도 교회의 공식 앱이 아니며 복음자료실과 동기화하지 않습니다.

질문 답변란에는 로그인 계정의 표시 이름 또는 비회원이 저장한 별명이 자동 입력됩니다. 직접 바꾼 별명이나 비워 둔 이름은 해당 답변의 초안에 보존되며, 입력란을 비운 채 등록하면 익명으로 표시됩니다. 계정을 바꾸면 이전 계정의 답변 초안은 표시하지 않습니다.
